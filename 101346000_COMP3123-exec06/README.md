## 🧠 Concepts Explained (Plain English)

### What is CI/CD?

Imagine you're writing an essay. Every time you finish a paragraph, you:
1. **Check for spelling errors** (that's **CI** - Continuous Integration)
2. **Submit it to your teacher** (that's **CD** - Continuous Deployment)

Without CI/CD, you'd have to manually check and submit every single time. With CI/CD, it happens **automatically** every time you save your work.

**In coding terms:**
- **CI (Continuous Integration):** Every time you push code to GitHub, a robot automatically runs your tests to make sure nothing is broken.
- **CD (Continuous Deployment):** If the tests pass, the same robot automatically publishes your website/app to the internet.

### What is GitHub Actions?

GitHub Actions is GitHub's **built-in CI/CD tool**. It's like a robot that lives inside your GitHub repository. You give it a list of instructions (called a "workflow"), and it follows them every time you push code.

**How it works:**
1. You create a file at `.github/workflows/deploy.yml`
2. Inside, you write steps like: "Install Node.js → Run tests → Deploy website"
3. GitHub reads this file and runs those steps automatically on their servers

### What is GitHub Pages?

GitHub Pages is a **free website hosting service** from GitHub. It takes HTML/CSS/JS files from your repo and makes them available as a real website at `https://yourusername.github.io/repo-name`.

**Think of it like this:** Your GitHub repo is a folder on your computer. GitHub Pages takes that folder and puts it on the internet for anyone to visit.

### What is `gh-pages` (the npm module)?

`gh-pages` is a helper tool that **pushes your built website files to a special branch** called `gh-pages` in your repository. GitHub Pages then reads from this branch to show your website.

**The flow:**
```
You write code → npm run build (creates /build folder) → gh-pages pushes /build to GitHub → GitHub Pages shows it as a website
```

### What is Jenkins?

Jenkins is an **open-source automation server** — basically the same idea as GitHub Actions, but you run it on your own computer or server instead of using GitHub's servers.

**GitHub Actions vs Jenkins:**
| Feature | GitHub Actions | Jenkins |
|---------|---------------|---------|
| Where it runs | GitHub's cloud servers | Your own computer/server |
| Cost | Free for public repos | Free (open-source) |
| Setup | Just add a YAML file | Install Java + Jenkins |
| Best for | GitHub-hosted projects | Enterprise/private projects |

## 🔧 Setup & Commands

### Step 1: Install dependencies
```bash
npm install
```
This installs `gh-pages` (listed in `devDependencies` in package.json).

### Step 2: Build the project
```bash
npm run build
```
This runs `src/build.js`, which copies everything from `public/` into a `build/` folder.

### Step 3: Deploy to GitHub Pages
```bash
npm run deploy
```
This does TWO things automatically:
1. Runs `npm run build` first (because of `"predeploy": "npm run build"`)
2. Then runs `gh-pages -d build` which pushes the `build/` folder to the `gh-pages` branch

## ⚙️ Understanding the package.json Scripts

```json
{
  "homepage": "https://cozyyyaria.github.io/101346000_COMP3123-exec06",
  "scripts": {
    "build": "node src/build.js",
    "predeploy": "npm run build",
    "deploy": "gh-pages -d build",
    "test": "echo \"All tests passed!\" && exit 0"
  }
}
```

| Script | What it does | When it runs |
|--------|-------------|-------------|
| `build` | Copies `public/` files to `build/` folder | When you type `npm run build` |
| `predeploy` | Runs `build` automatically before `deploy` | Automatically before `npm run deploy` |
| `deploy` | Pushes `build/` folder to `gh-pages` branch on GitHub | When you type `npm run deploy` |
| `test` | Placeholder test script | During CI or `npm test` |

**Why "predeploy"?** The `pre` prefix is special in npm. Any script named `pre<something>` runs automatically before `<something>`. So `predeploy` runs right before `deploy` every time.

## 🔄 Understanding the GitHub Actions Workflow

The workflow file (`.github/workflows/deploy.yml`) has two **jobs**:

### Job 1: Build
```yaml
steps:
  1. Download your code from the repo
  2. Install Node.js v20
  3. Run "npm install" to get dependencies
  4. Run "npm run build" to create the /build folder
  5. Upload the /build folder as an "artifact" (temporary storage)
```

### Job 2: Deploy
```yaml
steps:
  1. Wait for Job 1 to finish
  2. Take the uploaded /build folder
  3. Publish it to GitHub Pages
```

**What triggers this?** The `on: push: branches: [main]` part means: "Run this workflow every time someone pushes code to the `main` branch."
